# Templates

Copy and adapt these files into the project during setup or task planning. They are starters, not a required directory layout for every task system. Reconcile existing project documents instead of overwriting them.

- [PRODUCT-README.md](PRODUCT-README.md): terse index of product goal/invariant documents.
- [ARCHITECTURE-README.md](ARCHITECTURE-README.md): terse index of noun-based component documents.
- [architecture-component.md](architecture-component.md): starting structure for one cohesive architecture component, including optional stack, schema, and hierarchy notes.
- [AGENTS.md](AGENTS.md): project-specific instructions, commands, and QA affordances.
- [BACKLOG.md](BACKLOG.md): quick capture, distinct from official tasks.
- [task-card.md](task-card.md): Markdown official task-card starter when using the directory adapter.
- [brainstorm.md](brainstorm.md): orchestrator-created initial user details and appended Q&A rounds; copy to `TASKS/WIP/<task>/brainstorm.md`.
- [todos.md](todos.md): orchestrator-prepared execution plan, maintained by the worker; copy to `TASKS/WIP/<task>/todos.md`. Both files are required before dispatch.
- [outcome.md](outcome.md): completed task record and validation evidence.

Do not copy every template mechanically. Use the templates appropriate to the agreed task system and project.
